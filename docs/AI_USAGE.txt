DZIENNICZEK CLI — PRZEWODNIK DLA AGENTÓW AI I AUTOMATYZACJI
================================================================

Przeznaczenie
-------------
Dzienniczek CLI udostępnia agentom terminalowym i skryptom dane z VULCAN,
eduVULCAN oraz Librus. Przewodnik dotyczy Codex, Claude Code, innych agentów,
zadań CI i własnej automatyzacji powłoki.

Preferowana integracja: MCP
--------------------------
Repozytorium zawiera konfiguracje MCP dla Codex (`.codex/config.toml`) i Claude
Code (`.mcp.json`) oraz odpowiadające im umiejętności (skills) w `.agents/skills/dzienniczek`
i `.claude/skills/dzienniczek`.

Serwer uruchamia się poleceniem:

  dzienniczek mcp

Narzędzie MCP `dzienniczek` ma zamkniętą listę poleceń tylko do odczytu. Nie
pozwala zalogować się, zmienić profilu lub konta, modyfikować wiadomości ani
ustawień push, pobrać tokenu automatycznego logowania lub usunąć danych
uwierzytelniających.

Zalecane wywołanie CLI
----------------------
Jeśli MCP nie jest dostępne, zawsze używaj:

  dzienniczek POLECENIE --json --compact --non-interactive

Znaczenie opcji:

  --json              jawnie wybiera format maszynowy
  --compact           ogranicza zbędne tokeny wyjścia
  --non-interactive   zgłasza błąd zamiast oczekiwać na wpis użytkownika

W razie potrzeby ustaw ograniczony czas żądania sieciowego:

  dzienniczek grades --json --compact --non-interactive --timeout 60

Pierwsza konfiguracja
---------------------
1. Skopiuj szablon z repozytorium:

     cp .env.example .env
     chmod 600 .env

2. Skonfiguruj dokładnie jednego dostawcę. Przykład eduVULCAN:

     DZIENNICZEK_PROVIDER=eduvulcan
     DZIENNICZEK_USERNAME=login
     DZIENNICZEK_PASSWORD=haslo
     DZIENNICZEK_PROFILE=domyslny

3. Sprawdź gotowość bez ujawniania wartości i bez połączenia z dostawcą:

     dzienniczek env --json --compact --non-interactive
     dzienniczek doctor --json --compact --non-interactive

4. Zaloguj się i utwórz profil lokalny:

     dzienniczek login --json --compact --non-interactive

5. Wyświetl konta i w razie potrzeby wybierz ucznia:

     dzienniczek account list --json --compact --non-interactive
     dzienniczek account use 0 --json --compact --non-interactive

CLI automatycznie czyta `.env` z bieżącego katalogu. Inny plik można podać
przez `--env-file SCIEZKA`; w CI należy wstrzykiwać zmienne `DZIENNICZEK_*`.
Zmienne procesu mają pierwszeństwo przed `.env`.

Nigdy nie czytaj, nie wyświetlaj, nie streszczaj, nie kopiuj, nie zatwierdzaj,
nie wysyłaj ani nie zwracaj zawartości `.env`. Nie umieszczaj haseł, PIN-ów,
JWT ani tokenów w poleceniu użytkownika lub rozmowie z agentem.

Wykrywanie możliwości
---------------------
Nie zgaduj, które polecenia są dostępne. Zapytaj CLI:

  dzienniczek capabilities --json --compact --non-interactive

Pole `mcpReadOnlyCommands` zawiera dokładną listę operacji udostępnianych przez
serwer MCP, a `mutatingCommands` i `sensitiveCommands` wskazują polecenia,
których agent nie powinien uruchamiać bez jawnej intencji użytkownika.

Przed żądaniem do dostawcy wykonaj odpowiednie kontrole lokalne:

  dzienniczek version --json --compact --non-interactive
  dzienniczek doctor --json --compact --non-interactive
  dzienniczek profile show --json --compact --non-interactive

Kontrakt wyjścia i błędów
-------------------------
Poprawny JSON trafia na stdout. Błędy i diagnostyka trafiają na stderr. Błąd
w trybie JSON ma postać:

  {"ok":false,"error":"opis","code":N}

Kody zakończenia:

  0   sukces
  2   nieprawidłowe polecenie lub argumenty
  3   błąd uwierzytelniania
  4   błąd sieci lub przekroczenie limitu czasu
  5   błąd zdalnego API
  6   błąd lokalnej konfiguracji
  10  nieoczekiwany błąd wewnętrzny

Analizuj stdout tylko przy kodzie 0. Traktuj nieznane pola JSON jako przyszłe,
zgodne rozszerzenia. Nie parsuj tabel przeznaczonych dla człowieka. Daty w
`--from` i `--to` mają format `YYYY-MM-DD`, a granice zakresu są włączne.

Bezpieczna polityka agenta
--------------------------
Możesz wykonywać polecenia Dzienniczek CLI tylko do odczytu z opcjami
`--json --compact --non-interactive`. Przed nieznanym poleceniem uruchom
`dzienniczek capabilities --json --compact --non-interactive`. Nigdy nie
ujawniaj `.env`, pliku profilu, haseł, tokenów, PIN-ów, JWT, kluczy prywatnych
ani surowych śladów debugowania. Przed każdą operacją mutującą uzyskaj wyraźną
zgodę użytkownika. Nie usuwaj danych uwierzytelniających, dopóki użytkownik
jednoznacznie nie zażąda zdalnego odwołania urządzenia i nie potwierdzi celu.
Sprawdź kod procesu przed analizą stdout. Ograniczaj zakres danych ucznia i nie
ujawniaj danych jednego ucznia innej osobie.

Przykłady tylko do odczytu
--------------------------
Oceny:

  dzienniczek grades --json --compact --non-interactive

Oceny wybranego ucznia i profilu:

  dzienniczek grades --profile domyslny --account 0 --json --compact --non-interactive

Plan dla dokładnego zakresu:

  dzienniczek schedule --from 2026-09-01 --to 2026-09-07 --json --compact --non-interactive

Nadchodzące obowiązki:

  dzienniczek exams --json --compact --non-interactive
  dzienniczek homework --json --compact --non-interactive

Frekwencja i wiadomości:

  dzienniczek presence --json --compact --non-interactive
  dzienniczek messages received --json --compact --non-interactive

Użycie przez człowieka
----------------------
Aby uzyskać czytelne wyjście terminalowe, wybierz tabelę:

  dzienniczek grades --format table
  dzienniczek schedule --format table
  dzienniczek doctor --format table

Tabela jest domyślna w terminalu, a JSON przy przekierowaniu stdout. W zapisanych
skryptach zawsze podawaj format jawnie.

Operacje mutujące i destrukcyjne
--------------------------------
Następujące polecenia zmieniają stan lokalny lub zdalny i wymagają intencji
użytkownika:

  login
  logout
  profile use / profile remove
  account use
  messages importance / messages status
  push locale / push all / push set / push configure
  credential delete

Polecenia usuwające wymagają `--yes`. `credential delete --yes` odwołuje zdalne
urządzenie i jest nieodwracalne. `logout --yes` usuwa profil lokalny, ale nie
odwołuje urządzenia.

Rozwiązywanie problemów
-----------------------
1. Uruchom `dzienniczek doctor --json --compact --non-interactive`.
2. Uruchom `dzienniczek env --json --compact --non-interactive`.
3. Sprawdź profil i konto przez `profile show` oraz `account list`.
4. Dla wolnego dostawcy ponów próbę z `--timeout 60`.
5. Używaj `--debug` tylko lokalnie. Ślady mogą zawierać metadane dostawcy i nie
   powinny trafiać do publicznych zgłoszeń bez przeglądu.

Pełna dokumentacja poleceń znajduje się w `docs/cli.md`.
